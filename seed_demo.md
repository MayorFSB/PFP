## Филиалы (10)

отдельная таблица

1. Системные и идентификационные данные
• id (INT / UUID) — первичный ключ, уникальный идентификатор филиала.
• is_active (BOOLEAN) — статус филиала (активен / временно закрыт / удален).
• code (VARCHAR) — внутренний артикул или префикс филиала (например, MSK-01).
2. Основная информация и контакты
• name (VARCHAR) — публичное название филиала (например, «Парикмахерская №1 — Тверская»).
• legal_name (VARCHAR) — юридическое лицо для чеков и договоров (например, ООО "Салон-Тверская").
• phone_numbers (JSON / TEXT) — список контактных телефонов (может быть несколько: ресепшен, управляющий).
• email (VARCHAR) — контактная почта филиала.
• description (TEXT) — описание филиала для сайта или приложений.
3. Геолокация и адрес
• country (VARCHAR) — страна.
• city (VARCHAR) — город.
• address (VARCHAR) — улица, дом, корпус, строение.
• address_notes (TEXT) — ориентиры для клиентов (например, «3-й этаж, рядом с лифтом», «вход со двора»).
• latitude (DECIMAL) — географическая широта для карт.
• longitude (DECIMAL) — географическая долгота для карт.
• metro_stations (JSON / TEXT) — ближайшие станции метро и расстояние до них (актуально для крупных городов).
4. Время работы и настройки записи
• working_hours (JSON) — расписание работы по дням недели (например, {"mon": {"open": "10:00", "close": "22:00"}, ...}).
• timezone (VARCHAR) — часовой пояс филиала (важно, если сеть работает в разных регионах, например, Europe/Moscow).
• online_booking_url (VARCHAR) — ссылка на виджет онлайн-записи.
• booking_slot_step (INT) — шаг сетки записи в минутах (например, 15, 30 или 60 минут).
5. Финансы и эквайринг
• currency (VARCHAR) — валюта филиала (например, RUB, KZT).
• merchant_id (VARCHAR) — идентификатор платежного шлюза для онлайн-оплаты или интеграции с терминалом.
• tax_system (VARCHAR) — система налогообложения данного филиала.
6. Медиа и маркетинг
• logo_url (VARCHAR) — ссылка на логотип филиала.
• images (JSON / TEXT) — массив ссылок на фотографии интерьера салона.
• social_links (JSON) — ссылки на социальные сети и мессенджеры филиала (Telegram, WhatsApp, VK).

Также для аналитики

1. Параметры емкости и ресурсов (Capacity)
Эти данные нужны для расчета утилизации (загрузки) филиала — сколько салон мог бы заработать и сколько зарабатывает на самом деле.
• chairs_count (INT) — количество рабочих кресел/мест в парикмахерском зале.
• rooms_count (INT) — количество отдельных кабинетов (например, для косметологии, массажа, депиляции).
• wash_stations_count (INT) — количество моек (узкое горлышко: если моек мало, мастера будут простаивать в очереди).
• max_capacity_per_hour (INT) — максимальная пропускная способность клиентов в час при 100% загрузке.
2. Финансовая аналитика и P&L (Profit and Loss)
Колонки, которые помогают рассчитывать точку безубыточности (Break-even point) и чистую прибыль конкретной точки.
• rent_cost (DECIMAL) — фиксированная стоимость аренды помещения в месяц (для расчета постоянных расходов).
• communal_expenses_avg (DECIMAL) — средние коммунальные расходы и эксплуатационные платежи.
• square_meters (DECIMAL) — общая площадь помещения (нужна для расчета метрики «выручка/прибыль на 1 кв. метр»).
• target_revenue_month (DECIMAL) — плановый показатель выручки на месяц (KPI филиала).
3. Маркетинговые и клиентские метрики
Эти поля обычно рассчитываются автоматически (агрегируются из таблиц визитов и отзывов) и обновляются раз в сутки, но их важно иметь в карточке филиала для быстрой фильтрации и дашбордов.
• rating_aggregate (DECIMAL) — сводный рейтинг филиала на основе внутренних отзывов (или подтягиваемый по API из Яндекс.Карт/Google Maps).
• reviews_count (INT) — общее количество отзывов.
• nps_current (DECIMAL) — текущий уровень лояльности клиентов (Net Promoter Score) по филиалу.
• customer_acquisition_cost_limit (DECIMAL) — предельно допустимая стоимость привлечения одного клиента (CAC) для данного района/филиала.
4. Сегментация и гео-маркетинг
• district_type (VARCHAR / ENUM) — тип локации для кластеризации (например: спальный район, бизнес-центр, торговый центр, исторический центр). Помогает сравнивать филиалы со схожими паттернами поведения клиентов.
• competitors_count_radius_1km (INT) — количество прямых конкурентов в радиусе пешей доступности.
• target_audience_segment (VARCHAR) — доминирующий сегмент клиентов в этой точке (например: студенты, семьи с детьми, бизнес-сегмент).
5. Интеграции и логистика (Supply Chain)
• warehouse_id (INT / UUID) — ID основного склада, привязанного к этому филиалу, для контроля оборачиваемости расходных материалов (краски, шампуни) и товаров на продажу.
• franchise_id (INT / UUID) — если у вас франшиза, это ID франчайзи-партнера (для расчета роялти и разделения аналитики «собственные точки / франшизные»).

Дополнительно

1. Кадровый потенциал и HR-аналитика
В сфере услуг люди приносят деньги. Метрики штата необходимы для анализа текучести кадров и эффективности управления персоналом.
• staff_count_total (INT) — общее количество сотрудников, привязанных к филиалу.
• staff_turnover_rate (DECIMAL) — коэффициент текучести кадров (обновляется раз в месяц/квартал). Помогает BI заметить проблемы с менеджментом на точке.
• hr_manager_id (INT / UUID) — ответственный HR-специалист или управляющий филиала (для разграничения зон ответственности при разборе проблем).
2. Техническое состояние и Амортизация (OpEx/CapEx)
Филиал — это физический объект, требующий ремонта и обновления оборудования.
• last_renovation_date (DATE) — дата последнего косметического или капитального ремонта. Важно для BI: после ремонта обычно временно падает поток, но растет средний чек.
• equipment_value_total (DECIMAL) — балансовая стоимость всего оборудования в филиале (кресла, климазоны, вытяжки). Нужна для расчета амортизации.
• maintenance_status (ENUM / VARCHAR) — техническое состояние помещения (например: отличное, требуется косметический ремонт, критическое).
3. Безопасность, Инциденты и Юриспруденция
Аналитика рисков помогает компании не терять деньги на штрафах и кражах.
• incidents_count_ytd (INT) — количество зафиксированных инцидентов с начала года (жалобы, кражи, порча имущества, визиты проверок).
• has_video_surveillance (BOOLEAN) — наличие активной системы видеонаблюдения.
• sealing_permit_expiry_date (DATE) — дата окончания действия ключевых лицензий или разрешений (например, санэпидемстанции, пожарной безопасности, договоров на вывоз отходов).
4. Метрики Удержания Клиентов (Cohort & Retention Analysis)
Хотя эти метрики рассчитываются на основе визитов, хранение их текущих срезов в карточке филиала ускоряет построение BI-дашбордов.
• retention_rate_3m (DECIMAL) — коэффициент удержания клиентов за последние 3 месяца по этому филиалу.
• churn_rate (DECIMAL) — процент оттока клиентов.
• share_of_new_clients (DECIMAL) — доля новых клиентов в общем потоке (помогает понять, живет ли салон за счет "постоянников" или только на входящем трафике).
5. Инфраструктурные особенности (Удобства)
Маркетинговые теги, которые влияют на конверсию из просмотра карты в визит и объясняют аномалии в чеках.
• has_parking (BOOLEAN) — наличие собственной или доступной городской парковки (сильно влияет на премиум-сегмент).
• has_bar_cafe (BOOLEAN) — наличие зоны мини-бара/кофе для клиентов (дополнительный источник выручки).
• is_accessible (BOOLEAN) — доступность для маломобильных граждан или клиентов с колясками.

## Мастера (50-100 строк)

1. Системные и идентификационные данные
• id (INT / UUID) — первичный ключ, уникальный идентификатор мастера.
• branch_id (INT / UUID) — внешний ключ (FK), привязка к основному филиалу.
• is_active (BOOLEAN) — статус сотрудника (работает / в отпуске / уволен). Флаг для исключения из формы онлайн-записи.
• created_at / updated_at (TIMESTAMP) — дата добавления в систему и последнего обновления профиля.
2. Личные и контактные данные (Персонал)
• first_name (VARCHAR) — имя мастера (отображается клиентам).
• last_name (VARCHAR) — фамилия мастера (может скрываться в виджетах записи для конфиденциальности).
• phone (VARCHAR) — личный номер телефона для связи и авторизации в CRM.
• email (VARCHAR) — электронная почта.
• avatar_url (VARCHAR) — ссылка на фотографию мастера для сайта и приложения.
• bio / description (TEXT) — краткое описание, сильные стороны, девиз (для привлечения клиентов при онлайн-записи).
3. Профессиональный профиль и Квалификация
• specialization (ENUM / VARCHAR) — специализация (например: парикмахер-стилист, колорист, барбер, универсал).
• category_grade (ENUM / VARCHAR) — ранг/категория мастера (например: топ-стилист, ведущий мастер, младший мастер). От этого поля часто зависит базовый тариф на услуги мастера.
• experience_start_date (DATE) — дата начала общего стажа в профессии (для автоматического расчета «стаж: Х лет»).
• hire_date / termination_date (DATE) — дата приема на работу и дата увольнения.
4. Настройки онлайн-записи и Логистика
• is_available_for_online_booking (BOOLEAN) — разрешена ли самостоятельная запись к мастеру через интернет.
• booking_priority (INT) — приоритет при распределении «слепых» записей (когда клиент выбирает «любой мастер»).
• individual_slot_step (INT) — индивидуальный шаг сетки записи в минутах, если отличается от общего по филиалу.
5. Финансы и Расчет зарплаты (Payroll BI)
• salary_schema_id (INT / UUID) — ID схемы начисления зарплаты (процент от услуг, процент от продаж товаров, фиксированная ставка за выход или комбинированная система).
• personal_sale_percent_services (DECIMAL) — индивидуальный процент мастера за оказание услуг.
• personal_sale_percent_products (DECIMAL) — индивидуальный процент мастера за продажи товаров с витрины.
• hourly_rate (DECIMAL) — фиксированная ставка за час или за смену (если применимо).
6. Бизнес-аналитика и Эффективность (HR & BI Metrics)
Эти поля рассчитываются и обновляются в фоне (скриптами раз в сутки) для дашбордов управляющего.
• rating_aggregate (DECIMAL) — средняя оценка мастера на основе отзывов клиентов.
• reviews_count (INT) — количество оценок и отзывов, оставленных именно этому мастеру.
• retention_rate_3m (DECIMAL) — коэффициент возвращаемости клиентов мастера за последние 3 месяца (ключевой показатель качества работы парикмахера).
• utilization_rate_current (DECIMAL) — процент загрузки мастера (отношение оплаченного рабочего времени к общему времени смены).
• average_check (DECIMAL) — средний чек за визит к данному мастеру.
• upsell_rate (DECIMAL) — доля визитов, в которых мастер успешно допродал уход или косметику домой (в % от общего числа его клиентов).
7. Дополнительные и Портфолио
• portfolio_urls (JSON / TEXT) — массив ссылок на фотографии работ мастера (до/после).
• skills_tags (JSON) — теги ключевых навыков для быстрого поиска внутри CRM (например: ["Airtouch", "Стрижка пикси", "Оформление бороды"]).
• medical_card_expiry_date (DATE) — дата окончания действия медицинской книжки (критично для проверок).

## Клиенты(1000 - 50000 строк)


1. Системные и идентификационные данные
• id (INT / UUID) — первиччный ключ, уникальный идентификатор клиента.
• status (ENUM / VARCHAR) — статус клиента (например: активный, потерянный, спам/заблокирован).
• created_at / updated_at (TIMESTAMP) — дата регистрации в системе (первого визита) и дата изменения профиля.
• acquisition_channel_id (INT / FK) — источник привлечения клиента (например: Яндекс.Карты, таргет, рекомендация друга, вывеска) для оценки эффективности маркетинга (ROMI).
2. Личные и контактные данные
• first_name (VARCHAR) — имя (для персонализации в SMS/мессенджерах и обращения администратора).
• last_name / patronymic (VARCHAR) — фамилия и отчество (полезно для премиум-сегмента или юридических лиц).
• phone (VARCHAR) — основной номер телефона (уникальное поле, часто выступает логином).
• email (VARCHAR) — электронная почта для чеков и email-маркетинга.
• birth_date (DATE) — дата рождения (нужна для автоматических скидок и поздравлений).
• gender (ENUM) — пол (мужской, женский, не указан). Помогает сегментировать базу при рассылках акций.
3. Маркетинг и Лояльность (CRM)
• loyalty_program_id (INT / FK) — уровень в программе лояльности (например: «Базовый», «Серебряный», «VIP»).
• bonus_balance (DECIMAL) — текущий баланс бонусных баллов, доступных для списания.
• is_subscribed_sms / is_subscribed_push / is_subscribed_email (BOOLEAN) — согласия клиента на получение различных типов уведомлений и рекламы.
• referred_by_client_id (INT / FK) — ID клиента, который привел данного пользователя по реферальной программе («приведи друга»).
4. Профессиональные заметки и Специфика (Парикмахерская карта)
• hair_type_tags (JSON) — теги особенностей волос (например: ["сухие", "кудрявые", "седина >50%", "тонкие"]).
• allergy_notes (TEXT) — критически важные медицинские противопоказания и аллергии на компоненты красок или косметики.
• formula_notes (TEXT) — технологические карты окрашиваний (какие бренды красителей, номера оттенков и пропорции оксидов использовались в прошлые разы, чтобы другой мастер мог повторить результат).
• general_notes (TEXT) — комментарии администратора о предпочтениях (например: «любит крепкий кофе без сахара», «не любит пустую болтовню», «приходит с собакой»).
5. Бизнес-аналитика и Клиентский опыт (Customer BI)
Эти колонки рассчитываются автоматически агрегирующими скриптами и используются для построения дашбордов и RFM-сегментации.
• ltv_total (DECIMAL) — Lifetime Value: общая сумма денег, которую клиент оставил в сети за все время (услуги + товары).
• visits_count_total (INT) — общее количество совершенных визитов.
• no_shows_count (INT) — количество «неявок» (когда клиент записался, но не пришел и не предупредил). Порог для блокировки или предоплаты.
• average_check (DECIMAL) — средний чек клиента.
• last_visit_date (TIMESTAMP) — дата и время последнего визита (критично для фиксации оттока).
• favorite_master_id (INT / FK) — ID мастера, к которому клиент ходит чаще всего (более 70% визитов).
• favorite_branch_id (INT / FK) — любимый (самый посещаемый) филиал сети.
• rfm_segment (VARCHAR) — текущий RFM-класс клиента (например: Champions, About to Sleep, Lost), обновляемый раз в неделю.
